# Aero 交互体验需求

状态：需求与本轮评审决策已定稿，可据此拆分实施；不代表功能已经实现或通过验收。

整理日期：2026-10-10。

依据：原始《交互体验需求》图文、此前讨论共识，以及 2026-10-10 用户授权定夺后的评审决策。

本文以“必须／应”描述实施要求；第 12 节固定本轮的文件表达与兼容规则，第 13 节约束实现拆分，第 14 节记录已采纳的边界决策。实现可调整内部算法，不得自行改变交互、身份和文件兼容契约。

## 1. 目标与范围

在保留本地 Markdown 文件的前提下，提供一致的块操作体验：行首手柄、块菜单、类型转换、颜色、缩进与对齐、拖拽、剪贴板、段落链接、同步块、高亮容器、子文档和系统表情输入。

### 1.1 已确认的设计原则

1. **Markdown 保存必要信息**：允许在文件中保存少量颜色、对齐、容器等可读扩展标记，信息随文件迁移，不仅存在于应用数据库中。
2. **可读优先于外观兼容**：其他 Markdown 编辑器只需保证正文可读，不要求还原 Aero 的样式与交互；人和大模型能够从源码获知结构与样式信息。
3. **同步引用不保存正文副本**：修改原文后，引用处自动更新；引用处只读，不提供多处编辑。读取引用文档的大模型需要继续读取源文件才能获得内容。
4. **容器可嵌套，块样式独立**：高亮块可以包含其他高亮块；父容器不自动向子块传递文字颜色、对齐等样式。
5. **文档层级与目录解耦**：子文档的逻辑归属不受磁盘目录限制，不能为了改变逻辑父文档而强制移动文件。
6. **普通段落缩进只改变位置**：不因为增加或减少缩进而建立、解除块的父子关系。
7. **聚焦核心交互**：本轮不做外部应用通过链接唤起 Aero，不引入同步块的双向编辑或多人协作。
8. **操作不损坏内容与身份**：移动和类型转换不能悄悄丢失正文、子块、样式或已有引用标识；复制产生新的块身份。

### 1.2 非本轮范围

- 外部应用唤起、跨设备分享、公开访问链接和云端发布。
- 同步块引用处直接编辑、双向冲突合并和多人实时协作。
- 截图中出现但原始文字需求未要求的素材库、聊天、分享为图片、分栏、字体与字号控制等功能。
- 为实现这些交互而改用私有数据库作为文档内容的唯一来源。

## 2. 概念与操作对象

| 概念 | 定义 |
| --- | --- |
| 普通块 | 段落、标题、列表项、代码等可单独定位和操作的内容单位 |
| 容器块 | 拥有子块的结构节点，操作整个容器时包含其子树 |
| 高亮块 | 带独立背景、边框的通用容器，不等同于一段大文本输入框 |
| 行内高亮 | 选中文字的背景样式，与高亮容器不同 |
| 悬停高亮 | 表示当前操作目标的临时界面反馈，不写入文档 |
| 段落链接 | 指向某个块的导航引用，展示可点击的文档标题、段落摘要 |
| 同步块 | 在引用位置只读展示源块内容，源块变化后自动更新 |
| 子文档 | 独立的 Markdown 文件，在逻辑文档树上归属于父文档 |
| 块身份 | 用于追踪同一块的标识；需要跨保存、重开引用时必须持久化，不能使用仅会话内有效的编号 |

块菜单的操作目标、文本选区和插入光标是不同概念，不能因为菜单取得焦点就把操作对象换成另一个块。

### 2.1 操作粒度

| 命中对象 | 菜单、复制、剪切、删除与拖动的范围 | 转换与样式的范围 |
| --- | --- | --- |
| 普通段落、标题、代码、表格 | 当前完整块 | 当前块；特殊类型按适用范围禁用不支持的操作 |
| 列表项外侧、首段旁的手柄 | 整个列表项，包含续段和嵌套列表 | 列表类型转换只改当前项的标记；项级背景作用于整项，文字色、对齐作为本项直接正文的默认值 |
| 列表项正文内缘的子块手柄，含首段 | 当前子块及其拥有的子树 | 只作用于该子块；其显式属性优先于项级默认值 |
| 列表整体的外层手柄 | 整个列表 | 有序／无序转换作用于当前列表的直接项；不递归修改内层列表 |
| 高亮容器、引用容器的外层手柄 | 整棵子树 | 外框样式只作用于当前容器；没有自身正文的容器不提供文字色或对齐 |
| 同步引用的外层手柄 | 引用节点本身 | 不能转换或修改被引用的内容；可替换来源、复制、移动、删除引用 |

列表项默认值只供本项的直接正文使用，不向嵌套列表、引用或高亮容器传播；子段落的显式颜色和对齐可以覆盖默认值。普通容器仍遵循不继承子块样式的原则。

嵌套层级的操作区错开显示：一次命中只出现一个活动手柄；外层手柄位于对应容器外缘，列表整体手柄位于列表外侧顶部。不得把父子两级手柄叠在同一命中区域。

块选区只包含完整操作对象；同时选中祖先和后代时按祖先归并一次，不能重复复制或删除。字符选区限于同一个可编辑正文块，跨块扩展升级为整块选区，不把容器边界当成可删除字符。

## 3. 行首手柄与块菜单

### 3.1 显示与命中

- 鼠标悬停目标块的操作区时，显示“块类型标识＋六点手柄”，并轻微高亮目标块；不要求输入光标先移动到文本开头。
- 普通文本显示 `T`，标题显示 `H1` 至 `H6`，其他类型使用可辨认的对应标识。
- 操作区使用稳定的布局空间或叠加绘制，出现、消失、打开菜单均不得挤动正文、改变换行或导致块高度跳变。
- 鼠标从正文移向手柄或菜单时，操作目标保持稳定，不能在途中闪烁、消失或切换到相邻块。
- 嵌套容器中，应能分别命中子块和父容器的操作区，避免一次操作同时作用于多个层级。

### 3.2 点击与拖拽

- 点击六点手柄打开块菜单，不以“只选中块”代替打开菜单。
- 按下后移动超过拖拽阈值才开始拖拽；普通点击不能误触移动，拖拽结束也不能再触发一次点击菜单。
- 菜单始终绑定打开时的目标块，不跟随后续焦点变化误操作其他内容。
- 打开、关闭菜单不能修改文档；无法继续定位原目标时不得转而修改其他块。

### 3.3 菜单能力

菜单需要提供以下入口，具体排列可以参考原始截图，但不要求照搬所有截图菜单项：

- 普通文本、H1–H6、有序列表、无序列表、待办、引用、高亮块、同步块、代码块；同步入口是创建／插入引用，不作为覆盖原文的类型转换。
- 文字颜色、背景颜色及自定义颜色；高亮容器另有边框颜色。
- 增加缩进、减少缩进、左对齐、居中、右对齐、两端对齐。
- 复制、剪切、删除、复制段落链接。
- 新建子文档和系统表情可以通过插入菜单或斜杠菜单进入，不必塞入所有块的右键菜单。

## 4. 块类型转换

| 目标类型 | 行为要求 |
| --- | --- |
| 普通文本、H1–H6 | 调整块类型，保留正文、独立样式和块身份 |
| 有序／无序列表、待办 | 调整列表语义和标记，保留内容，不悄悄丢弃嵌套项 |
| 引用 | 使用引用结构，保留内部内容；复杂结构不能被直接截断 |
| 代码块 | 将可安全转换的内容承载为代码，不能因围栏冲突丢失正文 |
| 高亮块 | 包裹现有块或插入容器；解除容器保留其内部块，而非压成一段文本 |
| 同步块 | 源块菜单使用“复制同步引用”，插入菜单使用“插入同步块”；不执行“原文转换为自己的引用” |

- 空白位置的“插入新块”与已有内容的“转换当前块”需要明确区分。
- 块菜单、斜杠菜单及已有快捷键应使用同一套转换规则和撤销语义。
- 不要求任意复杂容器都能转换为任意单个叶子块；无法无损转换的选项置灰并说明原因。
- 一次转换作为一个完整的可撤销操作；撤销后恢复内容、结构、样式及引用身份。
- 解除容器涉及删除外层结构，与保留身份的普通类型转换不同；已有持久化身份的容器按第 6.2 节处理。
- 列表项改为普通文本、标题或代码时，仅在只有一个正文块、没有嵌套子树且能保留全部样式／身份的情况下整体转换；否则禁用并说明“此列表项包含多个块”。正文子块自身的转换不移除列表项结构。有序／无序／待办之间转换不受这个单正文限制，但必须保留整项子树。

### 4.1 拆分、合并与身份

- 段落中间按 Enter：前半保留原身份及全部历史别名，后半获得新会话身份；后半只有在被引用时才写入持久化 ID。段首／段末 Enter 只在前／后插入新块，原正文所在块保留原身份，不把身份交给空白占位。
- 拆分后的两块保留原来的显式块样式，行内样式按文字范围拆开；标题中间拆分时前半保留标题类型、后半为普通段落，列表项拆分时后半为同级新项，待办新项默认未勾选。
- Backspace 自动合并只适用于同一直接父节点下、相邻的段落／标题正文块；不跨高亮、引用或列表项边界直接吞掉结构。列表项开头优先执行退出／降低列表层级，再按正文合并规则处理，并保留该项原有子树。
- 合并保留前块类型、正文顺序和各段行内样式。块级颜色、背景、缩进、对齐及未知属性不一致时不自动合并，只将光标移到前块末尾，并给出“块样式不同，未合并”的轻提示。比较时排除身份、别名和归属元数据，不因双方 ID 不同而禁止合并。
- 只有一方有持久化 ID 时，合并结果保留该 ID；双方都有时，以前块 ID 为主 ID，将后块 ID 和双方已有别名并入结果的持久化别名。原有链接及同步引用均定位到合并后的完整块，不再承诺只展示原来某一半。
- 合并涉及旧短 ID 时先按第 12.3 节升级，升级与合并属于同一个撤销单位；不得把无文档作用域的旧短 ID 直接写成全库别名。
- 撤销拆分／合并必须恢复正文、样式、主 ID 和别名的原始归属；不为本轮引入可独立引用的字符范围。
- 空白编辑占位不强制写入身份；没有实际可引用节点时禁用复制段落链接和复制同步引用，输入形成块后恢复可用。

## 5. 样式、缩进与对齐

### 5.1 样式作用范围

| 入口／属性 | 作用对象 |
| --- | --- |
| 选区文字色、选区背景色 | 当前选中的文字，不擅自扩大到整个块 |
| 块菜单文字色、背景色 | 菜单绑定的目标块，不递归改写子块属性；列表项直接正文的默认值遵循第 2.1 节 |
| 高亮块背景、边框 | 当前容器自身的外观，不改写内部块的属性 |
| 对齐 | 块级属性，不只作用于选中的几个字 |
| 普通段落缩进 | 当前块的视觉偏移，不改变结构层级 |

高亮、引用等普通容器不自动继承文字样式：修改外层容器，不得重写内层块的颜色、对齐或缩进；子块没有背景时自然露出容器底色，这是绘制叠加，不是将父背景写入子块。列表项直接正文的显示默认值是第 2.1 节明确规定的例外，不复制到子块源码。

拖入、拖出容器应保留块自身的显式属性，不能把进入容器时看到的底色固化到块上。

### 5.2 颜色与取色交互

- 文字色、背景色提供预设色与自定义颜色；高亮容器边框也支持独立配色。
- 预设色随主题适配，自定义颜色保留准确色值，不在切换主题时偷偷替换成其他颜色。
- 自定义颜色应能表达截图中的 HEX／RGBA 信息，包括透明度；颜色序列化不得丢失精度或通道信息。
- 自定义取色过程只进行临时预览，不在每次拖动时写入 Markdown、触发保存或产生一条撤销记录。
- 确认取色后一次写入、一次撤销；取消或按 Escape 恢复进入取色前的样式。
- 恢复默认只清除对应属性，不清空其他样式、未知属性或引用标识。
- 配色前后选区和插入位置应稳定，不能因格式标记被隐藏或重新解析而选错文字。

### 5.3 视觉缩进

- 普通段落“增加／减少缩进”只左右移动当前块，不使其成为前一块的子块，也不改变其所属容器。
- 不通过在 Markdown 正文前插入若干空格来模拟视觉缩进，避免被解析成代码块或改变列表结构。
- 缩进可以存为独立的级数属性，减少到默认值时移除该属性；级数与界面距离的映射由布局统一处理。
- 列表原有的结构嵌套与普通段落的视觉缩进是不同操作，不能在没有明确结构落点或操作语义时混用。
- 本轮视觉缩进固定每级 24 pt，范围 0–8 级；继续增加会使可编辑区域窄于 160 pt 时禁用增加。手工源码超出范围时保留原值、显示按有效边界夹取，不能在打开文件时自动改写。
- 列表项菜单明确标为“增加／减少列表层级”，改变整项结构；普通段落菜单标为“增加／减少视觉缩进”。键盘 Tab 在列表项执行结构缩进，在其他正文中保持现有输入行为，不抢占代码缩进和焦点切换。

### 5.4 文字对齐

- 提供左对齐、居中、右对齐、两端对齐，不能只实现前面三种后将需求视为完成。
- 对齐在当前块扣除视觉缩进后的可用文字区域内计算，不通过填充空格实现。
- 编辑态与展示态使用一致的排版结果；光标、选区、点击位置、链接命中区域必须跟随实际字形位置。
- 对齐不改变正文内容，不把布局结果写成空格或手工换行，也不向子块传播默认对齐。
- 四种对齐适用于段落、H1–H6 以及列表项的直接正文；引用、高亮容器的外层入口置灰，内部正文仍可分别对齐。代码、数学、表格整体、图片和同步引用不提供文字对齐入口；表格单元格继续使用表格自身规则。
- 两端对齐只拉伸自动换行产生的非末行，段落末行和 Shift+Enter 结束的行左对齐；英文词间分配空隙，中日韩文字使用合法字间机会，组合字符、表情和英文单词内部不得拆开。不引入自动连字符或手工填空格。
- 输入法组合文本及候选面板定位使用相同的字形坐标；组合输入期间不切换编辑控件，不以暂停对齐制造跳变。

## 6. 高亮容器与嵌套编辑

- 高亮块是树形结构中的真实容器，可以包含段落、标题、列表、代码以及其他高亮容器。
- 每个子块使用与容器外相同的编辑、菜单、选区、配色、拖拽能力，不建立另一套功能受限的内部编辑器。
- 容器负责自身背景、边框和外框；子块负责各自的内容与样式。
- 整体移动容器时，内部所有子块及其相对顺序一起移动；单独移出某个子块不影响其他子块。
- 删除容器意味着删除整棵子树，必须可以撤销；“解除容器”则只解除外层包裹、保留子块内容和顺序，不能与删除混为一个操作。
- 嵌套情况下父、子容器均能单独定位和操作，禁止将容器拖入自身或自己的后代。
- 点击内部块不能把整个容器突然切换成一个大源码输入框，造成字体、边距、外框或高度跳变。

### 6.1 连续编辑与边界

| 场景 | 固定行为 |
| --- | --- |
| 新建空容器、删除最后一个子块 | 容器内保留可输入的空段落占位；占位可以仅存在于界面，不为此污染源码或产生单独撤销记录 |
| 子段落中间／末尾 Enter | 在当前容器内拆分／创建同级块；普通 Enter 不隐式退出容器 |
| 容器末尾的空段落再按 Enter | 在容器之后、当前容器的父节点内建立普通段落并移入光标；仅退出一层，不删除空容器 |
| 首个子块开头 Backspace | 非空时只定位到容器边界，不与外部前块合并；已有空占位时选中容器，随后一次删除才删除整棵子树 |
| 最后子块末尾向下、首个子块开头向上 | 跨边界移动光标至相邻可编辑块，不改文档；有前后内容时保持视觉列位置 |
| 跨块选中并删除 | 删除选中的完整节点；未选中的父容器保留，删除后没有子块则显示空占位 |
| 选中容器后直接输入 | 聚焦第一个可编辑子块，不以字符输入替换整个子树 |

上述“末尾空段落再按 Enter”在列表上下文中先遵循空列表项退出规则；到容器的直接空段落后才退出容器。引用容器使用同一套边界规则。

### 6.2 解除容器

- 没有持久化 ID、也没有历史别名的容器可以“解除容器”，将直接子块提升到父级原位置，保留全部子块身份、样式与顺序。
- 容器一旦具有持久化 ID 或别名，本轮禁用真正解除，说明“此容器有引用身份，解除会破坏引用范围”。判定依据是文件中的身份信息，不依赖可能不完整的反链索引，也不因当前检索到零条反链而放开。
- 这类容器仍允许将背景设为透明、边框设为无色；仅去掉高亮外观不删除结构和身份。不新增透明分组类型、范围锚点或把容器 ID 交给某个子块的机制。
- 删除容器仍是明确的删除操作，引用显示失效，撤销后恢复；不得把禁用解除误实现为禁止删除或禁止编辑内部内容。

## 7. 拖拽重排

拖拽预览必须明确区分三类结果：在目标之前插入、在目标之后插入、进入目标容器。

- 同级插入显示位置指示，进入容器显示对应容器的接收反馈，不能只画一条无法判断层级的线。
- 普通块移动自身，容器移动整棵子树；移动后保留身份、内容、样式和内部顺序。
- 拖入或移出容器属于明确的结构操作，不与普通段落“增加缩进”混淆。
- Escape、取消或落在不允许的位置时不修改文档，不留下空块、重复块或无意义撤销记录。
- 一次成功拖动是一个完整的撤销单位，一次撤销恢复整个移动，而非只撤销删除或插入的一半。
- 拖拽反馈不能挤动正文或反复重建整篇编辑界面；长文档中也应保持稳定的目标反馈。

## 8. 复制、剪切、粘贴与删除

- 块菜单“复制”将目标块写入剪贴板，不在原位置或下一行自动生成副本。
- 复制容器时包含其子树、顺序和样式；粘贴生成副本的新身份，不与原块共用引用标识。
- 已有持久化块标识随副本重建；尚不需要持久化引用的块，不因此要求全部强制写入标识。
- Aero 内部剪切再粘贴视为移动，保留原块身份和样式；不能因为保留了标识却没有更新定位关系，让引用指向错误位置。
- 在不同文档间进行内部剪切时，需要维护引用定位及相对资源地址，不能将原路径原样搬过去后悄悄产生错误链接。
- 删除作用于菜单目标；删除容器包含子块，删除同步引用不等于删除源内容。
- 撤销／重做应恢复本次修改对应的内容和结构；剪贴板中的文字、样式标记与编辑器显示结果应一致。
- 对外提供可读 Markdown 文本即可，不要求其他应用识别 Aero 的全部剪贴板结构。

### 8.1 内部剪切与跨文档事务

- 剪切立即从源文档移除内容，并保留可撤销记录；剪贴板同时提供可读 Markdown 和 Aero 会话内的单次移动令牌。尚未粘贴时可以直接撤销剪切；取消移动不清空系统剪贴板的可读文本。
- 同一笔记库、同一 Aero 会话内，首次成功消费有效令牌按移动处理。跨库、跨应用、重启后、剪切已撤销或令牌已消费，再粘贴均按复制处理，生成新身份；不承诺跨库维护原引用。
- 第一次内部粘贴将源剪切记录、目标插入、库内受影响引用改写和相对资源地址调整关联为一个工作区事务。源剪切记录不得仍可独立恢复出第二份相同身份的内容。
- 在任一参与文档撤销该事务，整体恢复到剪切之前：源位置恢复、目标移除、引用和资源路径恢复。重做同样整体执行；事务在所有参与文档共享同一个应用／撤销状态。
- 文档的后续普通编辑仍遵循各自撤销顺序。关联事务之后，其他参与文档已有后续编辑时，先要求撤销这些后续编辑，提示并提供前往对应文档的入口；不得静默连带撤销用户未选择的后续文字，也不得只撤销半个移动。
- 剪切至粘贴之间的无关编辑通过锚点维护原恢复位置；若位置已无法可靠恢复、发生外部冲突或身份重复，本次移动拒绝提交，不猜测插入位置。可读文本仍保留，允许用户明确按普通文本／副本粘贴。
- 提交前核对全部参与文档的内存版本、磁盘指纹和可写状态；需要改写的已打开文档使用当前缓冲区，不能覆盖尚未保存的文字。移动的资源保持原磁盘位置，改写相对地址指向原资源，不因块移动而搬迁或复制附件。
- 工作区事务采用持久化日志、写入前镜像及逐文件原子替换。成功提交并落盘后才报告移动完成、消费令牌；自动保存、关库和退出必须等待事务完成。只读、写入失败或版本冲突时取消提交，整体回滚，包括恢复源剪切内容。
- 准备期间主动取消也恢复源剪切内容；回滚完成后取消关联的剪切记录并作废移动令牌，再次粘贴只能作为副本。不能一边恢复源内容，一边保留还能再次搬入同一身份的令牌；恢复存在冲突时冻结令牌，待恢复处理完毕再作废。
- 多文件修改不宣称具备文件系统级同时原子性；崩溃后先按日志完成恢复或回滚，再允许相关文档继续写入。回滚期间遇到外部新改动时保留恢复副本并显示冲突，不覆盖外部版本，也不显示成功。
- 本轮引用维护范围为同一笔记库中纳入管理的 Markdown 文档；索引只用于找候选，提交前按实际文件校验。发现受影响文档无法安全读取或改写时事务失败，不能通过跳过它来宣布引用维护成功。

## 9. 段落链接与同步块

### 9.1 段落链接

- 可以为目标块复制链接，再粘贴到 Aero 内其他位置。
- 展示可点击的文档标题、段落摘要，点击后定位原块；不能与展开全文的同步块混为一种显示。
- 链接依赖可持久化的块身份，保存、关闭、重新打开文档后仍可定位，不使用会话内临时编号作为长期地址。
- 应用内移动块、重命名或移动文档时，应维护引用定位；改挂逻辑父文档不能使链接失效。
- 不因删除目标、重复标识或暂时解析不到目标而静默跳转到另一个相似段落。
- 本轮只覆盖 Aero 内部引用，不提供外部应用点击链接唤起 Aero 的能力。

文档身份、全库唯一的主块 ID、合并别名以及旧引用的解析顺序固定见第 12.3、12.4 节。移动改变位置，不改变长期身份；不以路径作为新引用的唯一地址。

### 9.2 同步块

- 原文是唯一内容来源，引用位置只保存引用，不保存需要反复同步的正文副本。
- 源块修改后，其他引用位置自动更新；引用位置只读，通过跳转原文进行编辑。
- 从某个位置删除同步引用不删除原文，也不删除其他位置的引用。
- 大模型或其他工具若只读取引用文档，只能知道引用目标，需继续读取源文件获得被引用内容。
- 与普通段落链接的区别是直接展示被引用内容，而不是只显示导航摘要。
- 同步范围为源块正文、显式样式及子块结构；引用节点外层只绘制来源提示和只读标识，本轮不支持独立颜色、对齐、缩进或宽度覆盖。

### 9.3 创建、刷新与嵌套同步

- 源块菜单“复制同步引用”只写入引用地址，不在源位置插入副本；首次引用所需的身份写入单独可撤销。粘贴到目标文档的独立块位置后只读展示。
- 插入菜单“插入同步块”打开来源选择器：先选文档，再选块，支持搜索、摘要预览及取消；取消不改文件。已有非空块上从块菜单使用同步入口时，只执行复制同步引用，不替换当前块。
- 来源确认后在保存的插入位置插入独立引用块。正文中途插入先按第 4.1 节拆分，引用位于前后两块之间；这次拆分与插入属于同一个目标文档撤销单位。跨文档来源仅补身份时，撤销插入保留来源 ID，避免破坏期间新产生的引用。
- 已有引用菜单提供“更换来源”和“前往原文”；更换只改变该引用的目标。选择器只允许当前库内可唯一定位的块，不选择尚未落盘的新文件或空白占位。
- 同一会话内优先订阅已打开源文档的内存修订，包括未保存输入、撤销与重做；未打开文档读取磁盘，并由文件通知失效缓存。发生外部冲突时继续展示带冲突提示的当前编辑缓冲区，不静默切换到另一版本。
- 嵌套同步允许展开，最大连续引用跳数固定为 3；高亮容器的结构嵌套不计为引用跳数。沿当前展开链追踪源身份，重复来源显示循环占位；超过 3 跳显示“继续前往原文”的占位，保留来源链接。无循环的重复引用可以在不同位置正常展示。
- 不存在、重复身份、读取失败、循环和超过深度分别显示可辨认的占位，不保存正文缓存到引用文件，不以最后一次成功内容冒充当前有效内容。

## 10. 逻辑子文档

- 新建子文档产生独立的 `.md` 文件，在逻辑文档树中挂载到当前文档下，并在当前插入位置提供子文档链接。
- 默认可以在当前文档所在目录创建文件，但逻辑归属不由目录推导，也不要求创建同名子目录。
- 父子关系的必要信息随 Markdown 文件保存，关系索引仅为可重建缓存，不能成为唯一真相。
- 文档改挂其他父文档时，修改逻辑关系即可，不强制移动磁盘文件。
- 文档自身身份应与标题、文件路径分开；改名或搬动文件不能被当成创建了一份完全无关的文档。
- 逻辑文档树是文档组织方式，不等同于同步块嵌入，也不因为正文中出现一个普通链接就自动建立父子归属。
- 一个文档最多一个逻辑父文档，禁止成环。删除或找不到父文档不连带删除子文档，保留原父 ID，文档树在“父文档缺失”分组展示；父文档恢复后自动恢复归属。

### 10.1 侧栏、创建与排序

- 侧栏提供“文档／文件”两个视图，默认文档树并记忆用户选择。文档视图按逻辑父子关系组织，文件视图继续按真实目录和附件组织；两种视图打开同一份文件，不复制内容。
- 文档视图拖动只改父关系和同级顺序，不能移动磁盘文件；文件视图拖动只移动磁盘路径并维护链接，不能隐式改变逻辑父文档。目录与文档不能混为一种可互相挂载的对象。
- 新建子文档默认在当前文档所在磁盘目录创建，名称为“未命名”，重名依次追加数字；写入文档身份、父 ID 和同级顺序，父文档插入导航链接后立即打开新文档，侧栏切到文档视图并定位。
- 创建文件、写入归属、插入父文档链接作为一个工作区事务。创建后尚无后续编辑时可以整体撤销；有后续编辑时遵循第 8.1 节的顺序约束，不能直接删掉已写入的新正文。
- 删除父文档正文中的子文档链接只删除链接，不解除归属或删除文件；解除归属通过文档树“移到顶层”，改挂通过文档树拖动或“移动到文档”入口。
- 同级顺序存于子文档的 `aero.order` 整数字段，初次按 1024 递增；重排优先取相邻序号间整数，无空位时在同一事务中重编号该组。缺少顺序的旧文档排在有序文档之后，按标题自然顺序、路径作稳定兜底；创建的新子文档追加到当前同级末尾。
- 文档／块身份重复时进入冲突状态，不自动认领其中一份；用户明确执行“作为副本导入”时为副本及其块生成新身份、重建内部引用，外部原有引用仍指向原件。

## 11. macOS 表情输入

- 在编辑位置提供入口调用 macOS 系统表情／字符面板，不实现独立的表情商店或私有图片格式。
- 打开面板时保存正确的输入焦点与插入位置，选择表情后通过正常文本输入路径插入。
- 表情按 Unicode 文本保存，继续支持移动光标、选中、复制、删除及撤销，不拆坏由多个码点组成的字符。
- 系统面板关闭或取消时不修改文档。

## 12. Markdown 表达与兼容契约

本节固定本轮实现采用的扩展语法，不代表现有解析器已经支持，也不把 Aero 扩展当作第三方 Markdown 标准。ID 示例仅用于说明结构，正式 ID 由程序生成。

### 12.1 独立样式

```markdown
# 标题 {align=center}

带视觉缩进的文字。 {color="#B42318" indent=1}

带自定义背景的段落。 {background="#FFF4CC"}

[独立配色的文字]{color="#2457A7"}
```

优先扩展现有属性列表机制，而非把样式放进私有数据库或大量内联 HTML；只存显式设置，保留不认识的属性，不在父子块之间复制样式。

预设文字色沿用 `.red` 等现有类名，背景沿用 `.bg-blue`，新增预设边框使用 `.border-blue`；预设色由主题映射。自定义色分别使用 `color`、`background`、`border-color`，支持 6／8 位 HEX 与 `rgba(R,G,B,A)`。HEX 规范为大写且保留输入通道，RGBA 的透明度为 0–1 的十进制值，必须保留输入精度；仅切换取色器显示格式不触发色值量化或写回。

同一颜色通道存在有效自定义键与预设类时，自定义键优先；多个预设类按现有行为取第一个，重复自定义键取最后一个有效值。修改某个通道时清除该通道所有已知旧类／键后写入选中值，恢复默认清除该通道全部已知表示；未知属性和其他通道原样保留。无效颜色值保留源码、不应用到绘制，并在对应颜色入口提示。

对齐使用 `align=left|center|right|justify`，视觉缩进使用 `indent=0..8`。段落尾固定顺序为“正文、属性列表、`^id`”；标题可使用现有标题属性位置，非段落块的独占元数据行紧随块后并与正文空行分隔。只修改实际操作涉及的属性，不在打开或保存时全文件迁移／规范化。

混合行内样式与身份示例：

```markdown
**重点**与[独立配色]{color="rgba(44,44,43,0.375)"}。 {.bg-yellow align=center} ^b-01arz3ndektsv4rrffq69g5fav
```

多行代码的外部元数据示例，代码内相同标记始终按代码字面量处理：

````markdown
```rust
let text = "正文 {.red} ^literal";
```

{indent=1 .bg-gray} ^b-01arz3ndektsv4rrffq69g5faw
````

列表项自身需要属性／身份时，在项内第一条独占元数据行标注 `aero-owner=item`，示例如下。它归属最近的列表项，不属于前后正文段落；列表标记和复选框后可以直接承载这行。没有项级设置的旧列表不补写此行。项内普通段落仍按普通段尾属性表达：

```markdown
- [ ] {aero-owner=item .bg-blue align=left} ^b-01arz3ndektsv4rrffq69g5fax

  第一段正文。 {color="#2457A7"}

  第二段正文。

  - 嵌套项，不继承外层项的文字色和对齐。
```

`aero-owner=item` 是归属标记，不是视觉样式；解析后不能留下一个可见的元数据段落。列表整体的属性／身份写在列表结束后的独占元数据行上。

### 12.2 嵌套高亮容器

```markdown
::::highlight {background="#FFF4CC" border-color="#E4B95B"}
# 一级标题 {align=center}

普通段落。

:::highlight {background="#E8F1FF" border-color="#4C7BE8"}
内部段落。 {color="#2457A7"}
:::
::::
```

外层使用比内层更长的冒号围栏，开始与结束围栏长度配对，避免嵌套边界歧义；内部代码围栏中的相似文本不能被误当成容器边界。向既有容器插入更深层时，事务可以延长受影响祖先围栏，但不得改写正文中的冒号字面量。

容器自身的样式位于开始围栏；身份与别名位于结束围栏后的独占元数据行。内部子块身份不能写在容器结束后，以免错误挂到容器：

```markdown
:::highlight {background="#FFF4CC" border-color="#E4B95B"}
子块正文。 ^b-01arz3ndektsv4rrffq69g5fay
:::

^b-01arz3ndektsv4rrffq69g5faz
```

### 12.3 块链接与同步引用

源文档中的可引用块：

```markdown
这是原文。 ^b-01arz3ndektsv4rrffq69g5fav
```

引用文档中的导航链接与只读同步展示：

```markdown
[[id:d-01arz3ndektsv4rrffq69g5fav#^b-01arz3ndektsv4rrffq69g5fav|开发记录]]

![[id:d-01arz3ndektsv4rrffq69g5fav#^b-01arz3ndektsv4rrffq69g5fav|开发记录]]
```

采用现有 Wikilink 外形，新增 `id:d-…` 的文档目标形式；只有匹配完整正式 ID 格式才按身份目标解析。新生成的长期段落链接、同步引用和子文档链接使用身份目标，`|` 后保留可读名称；界面来源标题和段落摘要按当前目标生成，可读名称作为源码提示，不使地址依赖标题。身份型笔记嵌入的 `|` 后也解释为可读名称，原有图片／PDF 的尺寸参数语义不变。真实文件名恰好匹配保留目标形式时，使用含 `.md` 后缀的路径引用明确按文件解析。

- 新文档 ID 为 `d-` 加 26 位小写 ULID，新主块 ID 为 `b-` 加 26 位小写 ULID；均在当前库中检查唯一。主块 ID 在被引用／参与身份迁移时按需写入，不给所有正文强制加标记。
- 文档链接通过文档 ID 定位；新块链接先在提示文档内解析，块已移动时通过全库唯一的主块 ID／别名查找当前位置。应用内移动仍在关联事务中维护库内引用的来源提示和旧路径引用；索引全部删除后，重新扫描 Markdown 即可恢复定位。
- 合并别名写作 `aero-aliases="b-旧块ID b-另一块ID"`，位于结果块的属性列表；主 ID 和别名使用同一唯一性约束，重复定义时明确报错，不按位置或相似正文任选一个。别名只属于承载它的块，不新增独立正文副本。
- 旧 `[[路径#^短ID]]` 继续支持，短 ID 保持文档作用域；不对全库按短 ID 猜测目标。旧块首次被复制长期链接、复制同步引用、跨文档移动或参与有身份的合并时升为新主 ID，同时在 `aero-aliases` 保留 `d-原文档ID#原短ID` 的有作用域别名，已有路径引用随事务维护。
- 升级短 ID 前先确保源文档有持久化文档 ID；相同短 ID 在不同文档中可各自升级，不发生跨文档抢占。原文档及别名恢复时仍可识别旧引用；旧路径已无法映射原文档时明确失效，不尝试全文相似匹配。
- 复制生成新主 ID，不继承历史别名；指向复制子树内部的引用按实际源目标映射到新身份，外部引用仍指向原件。合并和移动保留已有别名，拆分的别名跟随原身份。

### 12.4 文档父子关系

```yaml
---
aero:
  id: d-01arz3ndektsv4rrffq69g5faw
  parent: d-01arz3ndektsv4rrffq69g5fav
  order: 1024
---
```

在 front matter 的 `aero` 映射下保存 `id`、`parent`、`order`，避免占用用户原有顶层 `id`／`parent` 字段；顶层同名字段不自动解释为 Aero 元数据。顶层 `aero` 已存在且不是映射时报告元数据冲突，不覆盖原值。

旧文件第一次被长期引用、作为逻辑父文档或参与身份迁移时才补 `aero.id`；新建文档直接写入。没有父文档时省略 `parent`。保留其他 YAML 字段、注释和未知 Aero 键，不能用整段重新序列化悄悄删除用户信息。

现有索引数据库中的 note ID 不再作为唯一身份来源：实施时优先采用文件内 `aero.id`，索引重建得到同一身份。尚无持久化 ID 的普通旧文件可继续用缓存 ID，不因只读浏览批量修改用户笔记。

## 13. 实现方向与主要改造点

本节约束后续技术方案拆分，不是实施排期或已实现功能清单。第 12 节中的新语法均需解析、展示、编辑和往返支持，不能只生成文件标记而不支持读回。

| 层次 | 推荐方向与代码依据 |
| --- | --- |
| 文本与事务 | 保持 Markdown／Rope 为内容真相；[Document 编辑组](../../crates/aero-core/src/document.rs#L259) 只作为单文档原语，另建工作区事务、关联撤销与恢复日志，不能把它视为现成的跨文件事务 |
| 块与容器 | 基于现有 [Block 子树与属性](../../crates/aero-core/src/block.rs#L227) 扩展，不为高亮内部维护第二份内容；重点改造 [容器整体编辑单位](../../crates/aero-app/src/editor/units.rs#L60) |
| 样式 | 扩展 [现有颜色属性写回](../../crates/aero-core/src/colors.rs#L71)，统一自定义色、背景、边框、视觉缩进与对齐的解析、布局、写回和恢复默认 |
| 块操作 | 复用并扩展 [块拖拽入口](../../crates/aero-app/src/editor/block_menu.rs#L156) 与 [类型转换](../../crates/aero-app/src/editor/ops.rs#L528)，按稳定目标生成可撤销编辑，不让菜单各自拼接不一致的源码 |
| 引用与同步 | 扩展 [持久化块标识](../../crates/aero-core/src/block_refs.rs#L60)、[块链接复制](../../crates/aero-app/src/editor/toolbar.rs#L202) 和 [只读嵌入](../../crates/aero-app/src/editor/embeds_ui.rs#L1)，新增身份目标、别名与旧引用升级；跨文档订阅内存源修订，不能继续只读磁盘冒充实时同步 |
| 子文档 | 将逻辑父子关系与顺序作为 Markdown 元数据，侧栏提供逻辑文档树与磁盘文件树，身份索引改为以文件内 ID 为真相 |
| 排版与命中 | 现有输入层只有左／中／右对齐，两端对齐需要字形级排版与命中改造；浏览、输入、选区、链接、IME 坐标共用布局结果 |
| 表情 | 复用 [系统字符面板调用](../../forks/gpui-base/src/input/base/state.rs#L2418)，接入现有文本输入与撤销路径 |

主要工作量集中在可独立编辑的嵌套容器、四种对齐下统一的排版与命中，以及移动／复制／转换过程中的身份维护，不应把它们仅估算为增加菜单按钮。

实施顺序固定为“文件表达、身份及兼容往返 → 工作区事务与关联撤销 → 容器独立编辑和统一块操作 → 样式、四种对齐与命中 → 同步订阅及逻辑文档树 → 真实窗口与性能验收”。每步先完成自身回归，再开放依赖它的入口；不可将跨文件事务、两端对齐或独立子块编辑永久搁置后仍宣称本需求交付。

本次自定义颜色要求扩展了旧方案中仅支持预设颜色的边界；容器方案也会触及原有扩展语法预留范围，后续实现时应统一相关设计说明，而非在新旧约束间隐式切换。

## 14. 已定边界行为

以下为本轮已采纳的默认行为；详细规则以对应章节为准，不再保留为待讨论项。

| 情况 | 固定行为 |
| --- | --- |
| 同步范围 | 同步源块正文、显式样式及子块结构，不在引用位置保存一套独立可编辑副本 |
| 更新时机 | 同一 Aero 会话内的未保存源修改也刷新引用；外部文件修改通过文件变更通知刷新，不要求逐字读取磁盘 |
| 来源不存在或引用循环 | 保留分类占位与目标信息；最大连续引用深度 3，循环按当前链识别，不静默删除引用、不无限展开 |
| 文档改名或移动 | 应用内操作维护身份与引用；外部改动若无法可靠识别原身份，明确显示失效而不是猜测重定向 |
| 解除有身份的容器 | 有持久化 ID 或别名即禁用真正解包，不依赖反链数量；可设透明背景／无色边框，不转移身份 |
| 复制容器内的内部引用 | 对指向被复制子树内部的引用按新旧 ID 映射重建，指向子树外部的引用仍指向原来源 |
| 剪切内容被再次粘贴 | 第一次成功的内部剪切粘贴按移动处理，后续重复粘贴按复制处理，避免产生重复身份 |
| 子文档父关系 | 一个文档只有一个逻辑父文档，禁止父关系成环；其他位置通过普通链接或同步引用访问 |
| 删除或找不到父文档 | 不连带删除子文档；保留子文档并明确展示缺失归属，不因暂时缺失而静默改写关系 |
| 特殊块的对齐 | 对没有自身可对齐文本的容器置灰对齐入口并说明原因；不以递归修改子块代替容器对齐，不为此新增容器宽度控制 |
| 块文字色与行内颜色重叠 | 同一块内已显式设置颜色的文字优先于块文字色；这不是父子块之间的样式继承 |
| 拆分与合并 | 拆分由原正文前半保留身份；可合并块通过持久化别名保留双方链接，不同块样式不强行合并 |
| 跨库、重启后粘贴剪切内容 | 作为复制生成新身份，不保留有效移动令牌或承诺跨库引用维护 |
| 删除子文档导航链接 | 只删链接；逻辑归属通过文档树改挂或移到顶层 |
| 重复文档／块身份 | 报冲突并停止歧义定位，不自动选一份；显式作为副本导入才重建副本身份 |

### 15.1 性能验收口径

以下是未来交付门槛，不是已测得的数据。固定使用 release 构建、Apple M5 Pro／48 GB 参考机，记录实际 macOS 版本；窗口 1440 × 900 逻辑点、60 Hz，浅／深主题分别验证。CPU 微基准不替代真实窗口指标。

| 夹具 | 规模与内容 |
| --- | --- |
| P1 日常 | 1,000 块、约 1 MiB，中英混排，10 个可见同步引用，结构嵌套至 3 层 |
| P2 长文档 | 10,000 块、约 10 MiB，含列表、代码和高亮容器，结构嵌套至 8 层，100 个引用位置、最多 20 个同时可见 |
| P3 共享来源 | 同一源块被 100 处引用，分布于 10 个已打开文档，多个可见窗口并行刷新；另覆盖 3 跳展开与循环 |

- 预热完成后，每场景至少采样 200 次；输入到正确字形呈现 p95 ≤ 50 ms、p99 ≤ 100 ms；悬停反馈、菜单开关及拖动落点反馈 p95 ≤ 50 ms。持续滚动／拖动 30 秒，帧间隔 p95 ≤ 20 ms，不出现连续 100 ms 无反馈。
- 源停止输入至所有可见同步引用呈现最新修订 p95 ≤ 200 ms；外部文件变更从收到文件事件至可见引用更新 p95 ≤ 1 s。未在视口的引用允许延迟布局，但再次进入视口必须使用最新修订。
- 需要后台准备的跨文档事务在 100 ms 内显示处理中反馈；正确性优先，不用固定完成时限逼迫跳过引用校验。长事务支持提交前取消，提交开始后等待完成或回滚，不让取消留下部分修改。
- 重复开关菜单或仅改变悬停／拖动预览不增加全文解析次数；相同源修订的读取与解析可以共享，不能因引用位置数量重复执行同份源解析。结构修改允许必要的解析，须与纯反馈操作分开统计。
