## 复跑入口

```sh
# 第一次构建先下载经固定 SHA256 校验的 zvec 库
bash scripts/fetch-zvec.sh

# 格式检查与 core/index/app 测试；macOS 原生监听和废纸篓测试需要正常系统权限
bash scripts/check-m1.sh

# 从当前源码重建 ad-hoc .app，检查字典、rpath、签名、DMG 内容/挂载后签名、公证预检
bash scripts/check-m1.sh --bundle

# 原生 core/index 管线基准；生成并清理临时 vault，不读取个人笔记
cargo run --locked --release -p aero-index --example m1_bench -- 10000
cargo run --locked --release -p aero-index --example m1_bench -- 100000

# 可选：指定自己的真实 Markdown 语料，仅读取，不改写
AERO_CORPUS_DIR=/path/to/notes cargo test --locked -p aero-core --test roundtrip external -- --nocapture
```

自动验收日志：`target/m1-qa/check.log`。脚本检查正式三个 crate，不改变保留的 M0 spike 格式。未设置 `AERO_CORPUS_DIR` 时，外部语料用例直接返回；不能把它计为“真实笔记库已验收”。

`.github/workflows/m1.yml` 在 push/PR 执行相同流程，手动运行可启用 100k 性能门禁。工作流已添加，尚未推送或在 GitHub 实跑。选用标准 ARM64 macOS runner，依据 [GitHub runner 文档](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)；仅进行 ad-hoc 打包，不读取发布证书或提交公证。

| 磁盘校验/读取失败停止保存 | 自动通过 | `unreadable_disk_state_stops_saving` |
| 同名冲突副本不覆盖 | 自动通过 | 原子 create-only 发布 + `repeated_conflicts_keep_every_disk_version` |
| 保存失败阻止切换笔记、关闭/切换 Vault | 自动通过 | `failed_save_blocks_note_and_vault_switching` |
| 普通退出/关窗前保存检查 | 已接入；原生关窗人工复核待做 | Quit handler、`on_window_should_close`；强杀/系统终止不属于可取消退出 |
| 退出时索引引擎关闭顺序（2026-09-16 三份 `libzvec_c_api` 崩溃报告） | 修复，本机通过 | `SearchService::close_blocking` 在主线程 join 同步线程、flush、关句柄；`Drop` 同路。应用包身份启动、建好索引后 / 同步途中各退 5 次，退出码全 0、无新崩溃报告；`close_blocking_releases_the_engine_for_reopen`、`dropping_mid_sync_stops_the_thread_and_frees_the_lock` |

| wikilink 点击 → 打开 / 建笔记 / 撤销 | 自动通过，原生人工点击待做 | `clicking_a_wikilink_in_the_preview_opens_target_and_reveals_heading` 等以真实原生事件分发覆盖 |

保存保护不等于三方合并：当前仍保留双方版本，由用户决定。跨进程写入在校验与 rename 之间的竞争、崩溃恢复/系统强制退出另需专项设计和测试，不将本次结果扩展为“任何情况下均不会丢数据”。

## 性能验收

见 [性能实测与方法](performance.md)。基准使用真实 `Vault → Document → SQLite → zvec` 管线。100k 模式对全文查询 p95 < 50 ms、全量重建 < 180 s、保存后可搜索 < 300 ms 设置失败退出；GUI 首帧/输入绘制与内存门禁未伪装成无头测试。
