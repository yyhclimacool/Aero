## 写回层（`crates/aero-core/src/colors.rs`）

- 调色板与 Notion 对齐的 9 色：`gray brown orange yellow green blue purple pink red`。文字色直接用类名（`{.red}`），背景色加 `bg-` 前缀（`{.bg-blue}`），两组可叠加（红字 + 黄底）。
- `Slot::{Text, Background}` 负责类名与调色板的对应关系：`class()` 生成、`owns()` 判定归属、`color_of()` 从属性列表读回当前颜色。不在调色板里的类名不归任何一组。
- `block_color()` 读块末属性列表里的颜色；`block_edit()` 生成块上色 / 去色的源码编辑：
  - 新上色在块末追加 ` {.类名}`（前面留一个空格，符合 6.3.10 的识别规则）；
  - 换同组颜色只替换这一组，另一组保持不动；
  - 「默认」＝移除这一组，属性列表空了就把 ` {...}` 一起删掉；
  - 不认识的类名、`key=value`、`#id` 全部原样保留，`^id` 始终留在属性之后（`正文 {.red} ^para-id`）；
  - 已经是该颜色、或要移除但本来就没有时返回 `None`（不产生编辑、不脏文件）；调色板外的颜色一律拒绝。
- 标题与 Pandoc 的 header attributes 一致（`# 标题 {.orange}`）。comrak 把标题的属性列表收进 `ast.attrs` 但 sourcepos 仍含 `{...}`，解析器现在把它按段落同样的规则记成 `suffix_len`：编辑态与渲染态都不再出现这一段源码。
- `inline_edit()` 生成行内颜色的源码编辑，按 6.3.10 的写回规则：
  - 没有承载者就包一层 `[文本]{.类名}`；选区恰好是一个行内元素（`**粗**`、`` `码` ``、`~~删~~`、`==高亮==`、`*斜*`）时属性直接挂在元素后（`**粗**{.blue}`），不再多包 `[ ]`；
  - 已有 `[文本]{...}` 或 `元素{...}` 时就地改这一组，另一组与未知属性保持不动；
  - 去色后属性列表空了连 `{}` 一起收掉，包裹用的 `[ ]` 也一并去掉；
  - **黄色背景**返回 `Inline::Highlight`，由调用方走 `inline_format::plan(.., Format::Highlight)` 写成 `==文本==`（兼容性最好，切换逻辑与 `⌘⇧H` 一致）；
  - 选区跨行、纯空白、重复上色、调色板外的颜色一律不产生编辑；改完用 `same_structure` 校验块结构没变，否则拒绝。

## 色值令牌（`crates/aero-app/src/colors.rs`）

- 13.3 的 `content.text.*` 与 `content.bg.*`：9 色 × 两组 × 浅深两套。深色下文字色提亮、背景色降饱和压暗，不做简单反相。
- 对比度按 WCAG AA 取值并有回归守着：**文字色对编辑区底色 ≥ 4.5:1**（浅色 `#ffffff`、深色 `#0a0a0a`），**正文色对背景色 ≥ 4.5:1**（浅色 `#0a0a0a`、深色 `#fafafa`），背景色与编辑区底色明显不同。
- `content.bg.yellow` 就是 `==` 的高亮色（浅 `#fef08a` / 深 `#66551c`），源码态与预览态、`==` 与 `{.bg-yellow}` 都落到同一个令牌。
- `paint_html()` 把 core 生成的颜色类名换成当前主题的色值：core 不认识主题，只写 `<span class="red bg-blue">` 与 `<mark>`。

## 预览上色

- **块颜色**：`Block.attrs` 里的颜色在 `editor/mod.rs` 的渲染路径上生效。背景在最外层那个带颜色的块上铺一次（铺满块矩形、左右各多 8 px、6 px 圆角，含子块），文字色往下传给子块与 `TextViewStyle` 的正文色，`- 列表项 {.green}`、callout 正文、引用里的段落都跟着变。
- **行内颜色**：`aero_core::highlight::preview` 从"只处理 `==`"扩展成"`==` 与行内属性列表共用一条路"。做法是先扫出承载者（`[文本]{...}` 与紧跟行内元素的 `{...}`，含 comrak 自己解析掉的行内代码 / 链接属性），把标记换成私有使用区的哨兵字符后重新解析，生成 HTML 时再把哨兵换成 `<span class="…">`；代码、数学、HTML、转义 `\[` 里的 `{...}` 不算属性列表，引用式链接那种被两种形式同时认出的只算一处。跨硬换行的 span 每行各自开合，HTML 始终配对。
- 属性列表本身不进渲染：`[文本]{.red}` 预览出来就是"文本"，调色板外的类名（`{.custom}`）同样只隐藏标记、不上色。
- gpui-base 的富文本层原来只有 `<mark>` 的背景色，没有文字色。仓库内 `forks/gpui-kit/crates/base` patch 给 `TextMark` 加了 `color`，并让 `<span style="color: …; background-color: …">` 落到文字色与高亮底色；显式颜色压过链接色（`[链接](url){.red}` 是红的）。

## 颜色菜单（`crates/aero-app/src/editor/color_menu.rs` + `colors_ui.rs`）

- 打开方式：`⌘/`（14 节里块菜单的键位——块菜单还没做，先直接打开它唯一做好的这一项；再按一次关掉）、`/颜色`、命令面板的「颜色…」、编辑菜单的「颜色…」、选区浮动工具条的 `A ▾`。都走同一个 `Editor::open_color_menu`。
- 版式按 7.7：「上次使用」一行（真实颜色的 `A` + 完整名字 + `⌘⇧H`，点它等于按那个键）、过滤输入框、文字组、背景组；每组「默认 + 9 色」按每行 5 个折成两行，样本用 13.3 的 `content.*` 色值画 `A`（文字组染前景、背景组铺底），当前已有的那个颜色带 `✓`。
- **过滤输入框是对设计稿的一处补充**：菜单要能按「蓝」筛，就得有真正的输入控件接输入法。匹配中文名（「蓝」）、完整名（「蓝色背景」）、英文颜色名（`blue`）、类名（`bg-blue`）、组名（「文字」/「背景」/`bg` 整组命中）。
- 键盘：`←→` 沿阅读顺序走一格（两头回绕）、`↑↓` 换行并尽量保持列号（目标行更短时落到行尾）、`⏎` / `Tab` 应用并关闭、`Esc` 只关菜单（不改文档、不退出编辑态）。点样本等于确认，点到菜单外面关掉。
- 菜单开着时焦点借给它的过滤输入框：编辑态的控件、选区、编辑态本身都留着（与命令面板借焦点同一套规则，失焦照样落盘）。关闭后焦点回控件（编辑态）或编辑器容器（块选中态）。
- **改哪里在打开那一刻就定下来**：编辑态有选区 → 那段文字（行内颜色）；编辑态没选区 → 当前块；块选中态 → 选中的那几块（一个撤销组）。多块选中时不显示 `✓`（各块颜色未必一样）。
- 应用之后记住这次的颜色，`⌘⇧H` 与菜单第一行接着用它。
- `/` 菜单（7.1）：`/颜色` 开菜单；`/红色`、`/蓝色背景`、`/默认背景` 直接给当前块上色。颜色只在输入了东西之后参与匹配（"直接命中"），不会把默认的 `/` 菜单刷满 20 项；候选行左边画真实颜色的样本。
- 菜单位置：编辑态跟着光标（与 `/` 菜单同一套），块选中态贴在选区头那一块下面（那一块每帧把自己的矩形记在 `head_bounds` 里）。

## `⌘⇧H`：应用上次使用的颜色

- 键位从"固定黄色高亮"改成 `ApplyLastColor`。「上次使用的颜色」是应用级状态（`colors::Last`），默认**黄色背景**——没用过颜色菜单时 `⌘⇧H` 与从前完全一样（写 `==文本==`）。
- 编辑态作用于选中的文字，块选中态作用于选中的块（多块一起改，合成一个撤销组）。上色后选区仍然盖在原来那段文字上，可以接着换颜色。
- 命令面板有「应用上次使用的颜色」，编辑菜单里在「黄色高亮」下面。
- 颜色菜单接上后调用的是同一个入口 `Editor::apply_color(slot, color)`；`colors::remember()` 负责记住选择。

## 自动化

这一轮新增 6 项回归（core 1、app 5），全量 **491 项通过**（app 263、链接绘制集成 17、core 155、往返 5、index 50、反链计数集成 1）。

```sh

```

- `colors::…`（core）：块上色 / 叠加 / 去色 / 未知属性与 `^id` 保留、读回、调色板往返、行内包裹 / 就地改 / 去色收括号 / 黄底走 `==`。
- `inline_attributes_become_color_spans_and_hide_their_markers`（core）：`[文本]{...}` 与元素后挂属性都变成 `<span class>`，两组叠加的类名顺序固定，嵌套、硬换行、标题、表格单元格都对；代码 / 数学 / 转义 / 普通花括号不误判；引用式链接只算一处。
- `content_tokens_meet_aa_contrast_in_both_themes`：18 个文字色令牌对底色、18 个背景色令牌对正文色都 ≥ 4.5:1。
- `every_palette_color_has_a_token_in_both_slots`：令牌覆盖整个调色板、深浅两套不同、调色板外类名不上色、`bg.yellow` 与 `==` 同色。
- `paint_html_resolves_palette_classes_to_theme_colors`：类名 → `style` 的映射，未知类名不上色。
- `block_color_is_written_at_the_block_end_and_painted_in_preview`：块选中态 `⌘⇧H` 写 `{.bg-yellow}`、重复按不再产生编辑、浏览态铺出块底色、撤销后底色消失。
- `block_colors_cover_every_selected_block_in_one_undo_group`：多块选中一起上色（含标题）、两组叠加、一次撤销退掉整组、「默认」去色。
- `inline_color_wraps_the_selection_and_paints_it_in_preview`：`⌘⇧H` 按上次颜色包出 `[文本]{.bg-blue}`、选区保持、预览画出行内底色、撤销后消失；文字色不画成底色。
- `inline_colors_are_read_back_from_their_carrier`（core）：从 `[文本]{...}`、元素后挂的属性、`==文本==` 读回颜色；未知类名与空选区读不出。
- `items_cover_both_slots_and_the_default_entry` / `filter_matches_chinese_english_class_names_and_whole_groups` / `keyboard_walks_the_grid_by_rows_and_wraps`：菜单条目编号与名字、四种过滤写法与整组命中、网格走位与回绕。
- `color_menu_filters_and_applies_to_the_selection`：`⌘/` 打开、20 项、输入「蓝」筛成两项、`↑↓` 换行、`⏎` 写出 `[文本]{.blue}` 并关闭菜单、焦点与选区回到正文、记住颜色、再打开时 `✓` 落在蓝色上、`Esc` 不改文档也不退出编辑态。
- `color_menu_colors_blocks_when_no_text_is_selected`：没选区时改当前块（`bg` 整组 + `→` + `⏎` → `{.bg-gray}`，文本框里看不到属性）、块选中态两块一起上色且选区保持、一次撤销退回。
- `colors_join_the_menu_only_once_something_is_typed` / `slash_colors_hit_directly_or_open_the_menu`：`/` 菜单里颜色只在输入后出现、`/蓝色背景` 直接命中并删掉命令文字、`/颜色` 开菜单。这一条同时盯着上面那个字节切片崩溃（`段落 /蓝色背景` 正好踩中）。

## 尚未实现 / 已知限制

- **选区浮动工具条（5.9）**：已交付，见 [选区浮动工具条验收](m2-toolbar.md)。`A ▾` 打开本菜单。
- **块菜单（5.3）里的"颜色 ▸"**：块菜单本身在 M2 之后，`⌘/` 眼下直接开颜色菜单；块菜单做出来时它会变成菜单里的一项。
- **"应用到整块"开关**：7.7 说选区正好覆盖整块时菜单顶部多一个开关，现在没有——想给整块上色就把光标放在块里、不选任何文字再开菜单。
- **菜单里没有滚动条**：条目固定 20 项，一屏放得下。
- **源码态的淡色标记**：7.7 要求源码态把 `{.red}` 与 `[`/`]` 显示成淡色标记。块末属性是尾部标记（编辑态本来就看不到），行内的 `[文本]{.red}` 在编辑态就是普通源码，没有淡化。
- **块选中 / 搜索定位高亮期间**块自己的底色被临时状态盖住（一个元素只能有一种背景），文字色照常。
- **行内背景没有 2 px 圆角**：GPUI 的行内背景是矩形，与 `==` 高亮一样。
- **行内文字色没有像素级回归**：单元测试里不光栅化字形，只能断言"文字色不画成底色"；文字色的实际观感要人工看一眼。
- `_下划线强调_` 放在 `[..]{.red}` 里时不再是强调（哨兵字符落在下划线两侧，CommonMark 的词内规则不再成立）；`*斜*` 不受影响。
- **多行块的独占行属性**（6.3.10 末尾那种 `{.bg-gray}` 单独一行）：写回只处理块末形式；渲染会跟着 `attach_markers` 生效。
- **链接 / 嵌入形态的行内元素**：`[链接](url)`、`![[嵌入]]` 作为选区时按"包一层"处理（由结构校验兜底），还没有按元素形态挂属性。
- 文字色与背景色叠加（红字 + 黄底）不保证 AA——与 Notion 一样，那是用户自己的选择。
