# M2 嵌入 / 附件补全验收

日期：2026-09-18。

## 功能范围

- 输入 `![[` 列出笔记、图片和 PDF，显示类型及完整路径，支持标题 / 文件名 / 路径模糊筛选，最多 8 条；最近笔记、本篇 `.assets/` 附件及同目录附件有排序加分。普通 `[[` 菜单仍只列笔记。
- `↑↓` 选择，`⏎` / `Tab` / 鼠标确认，`Esc` 关闭；一次插入可单步撤销 / 重做。有现成 `]]` 时复用，光标留在末尾，不重复插入 `!`。无匹配时只插入未解析嵌入源码，不创建文件。
- `![[笔记#` / `![[笔记#^` 复用标题和块选择器；`![[#` / `![[#^` 使用当前未保存笔记。块 ID 仅在确认时写入，同篇补 ID 与插入嵌入组成一个撤销组；跨篇撤销保留目标 ID，沿用已有指纹检查与字节保持逻辑。
- 嵌入的 `|` 后是尺寸等参数，`⇧⏎` 与 `⏎` 一样只插入嵌入，不生成显示别名。编辑带参数的现有嵌入、或在带片段的现有嵌入内编辑笔记名时不打开补全，保留原始源码。
- 支持中文、引用 / callout、表格源码；代码、数学、转义和 URL 内不触发。输入法预编辑不写文档、不确认候选；提交后再筛选。普通链接、嵌入、标题及块模式切换后，旧请求不能覆盖新菜单。
- 附件在后台枚举，进入 `.assets/`，遵守隐藏文件、`.gitignore` 和 `.aero/ignore` 规则；不跟随文件或目录符号链接，不读取 / 修改附件内容，不依赖全文索引。确认前检查附件仍是 vault 内的普通文件，加载 / 读取错误不当作空结果。
- 附件按本篇 `<note>.assets/` → 笔记相对路径 → 显式 vault 路径 → 唯一文件名解析，不区分大小写。限定路径缺失时不退化成另一个同名文件；同名候选生成经解析校验的限定路径，无法表示时提示并保留输入。拒绝绝对路径和 `..`。
- 图片 / PDF 后缀保留给附件，同名笔记使用 `.md`，例如 `![[photo.png.md]]`。`![[paper.pdf#` 不误列 `paper.pdf.md` 的标题 / 块；显式写 `.md#` 可补全。重命名笔记时不改同名附件嵌入，新名字具有附件后缀时也保留 `.md`。
- 核心提供 `scan_embeds`，返回含 `!` 的 UTF-8 范围、目标、片段和参数；普通链接扫描仍排除嵌入。尺寸参数和 PDF `#page=` 仅识别源码，此次未接入渲染。

## 2026-09-22 补充：嵌入内容渲染

- `![[笔记]]`、`![[笔记#章节]]`、`![[笔记#^块]]` 独占一段时只读渲染目标内容：左侧竖线 + 一行来源标题（章节 / 块会带上片段），点击容器按 wikilink 同一条路打开来源并定位。
- 渲染的是目标**源码**，交给同一套预览渲染器，所以嵌入里的标题、行内格式、表格、callout、图片都照常渲染。整篇嵌入不带目标的 front matter（属性属于那篇笔记）。
- 同篇嵌入用未保存的文档，改一处两处一起变；跨篇在后台读盘并缓存。嵌入内容由预取维护（打开笔记、正文变化、笔记目录就绪、缓存失效各触发一次），渲染只读缓存——渲染过程中不修改编辑器自身。
- 被嵌入的笔记保存 / 外部改动 / 删除后，工作区让嵌入缓存失效并重读；片段消失时变成「源码 + 错误」，不会拿旧内容糊弄。
- 解析不到、同名歧义、片段找不到都落到「源码 + 一行错误」，内容永不丢失、不写文件。
- 嵌入里还能再嵌入，但只渲染一层（`EMBED_DEPTH = 1`）：更深的层级显示源码，互相嵌入不会转不出来。PDF 嵌入仍保持源码（属 M3）。

新增回归 `note_embeds_render_their_target_and_follow_changes`（app）与 `embeds_ui` 的两项片段切片测试：整篇 / 章节 / 块各自的源码范围、front matter 剥离（含 CRLF 与未闭合的 `---`）、同级标题截断、自嵌套不递归、来源改动后重读、片段消失后报错。全量 **465 项通过**（app 245、链接绘制集成 17、core 147、往返 5、index 50、反链计数集成 1）。

## 2026-09-22 补充：附件树展示与引用计数

- 文件树里 `*.assets/` 仍不作为文件夹出现；有附件的笔记行右侧显示 `📎<数量>`，点它展开 / 收起附件子行（点徽标不会顺带打开笔记）。附件行只读，双击用系统应用打开，不参与行内重命名。
- `aero_core::attachments::References::read(vault)` 扫全库算引用计数：`![[附件]]` 嵌入、普通 Markdown 图片 / 链接、生效的引用式定义都算，代码 / 数学 / 转义里的写法不算（与改名事务共用扫描）；`./` 与 `../` 会归到 vault 内路径，越过根目录的忽略。按出现次数计，一次都没被引用的就是孤儿。
- 报告由工作区在后台算（读每篇笔记正文），算完交给文件树把没人引用的附件标成「未引用」。报告还没算出来时不显示任何标记，避免把正常附件误标成孤儿。
- 触发时机：打开 vault、附件变化、目录重扫。只在笔记里加减引用不会立刻刷新计数（下次附件变化 / 重扫 / 重开生效）——这是为了不让每次保存都重读整库。

新增回归：core 的 `attachment_references_count_real_uses_and_report_orphans`（嵌入 + 图片 + 引用式定义 + 相对路径各计一次，代码块里的不算，孤儿列表按路径排序）与 `relative_targets_are_rebased_and_cannot_escape_the_vault`；app 的 `attachments_fold_under_their_note_and_mark_unreferenced_ones`（附件目录不当文件夹、默认折叠、点 📎 展开 / 收起、报告到位后才标未引用）。全量 **468 项通过**（app 246、链接绘制集成 17、core 149、往返 5、index 50、反链计数集成 1）。

**「未引用」不等于可以安全删除**，因此目前不提供按孤儿批量删除的入口。会算出假 0 的情况：同名附件造成目标歧义时两个都不计数（`Ambiguous` 不计）；读不出来的笔记（权限、非 UTF-8）被整篇跳过，它的引用全部丢失；被 `.gitignore` / `.aero/ignore` 或隐藏目录排除的笔记不在枚举范围；内联 HTML 的 `<img src>` 不算（扫描只认 Markdown 的 Link / Image 节点）；百分号编码的地址解析不到同一个文件；vault 外部（导出站点、别的库）的引用无从得知。加上报告不是实时刷新，刚写下的引用可能还没算进去。将来要做删除入口，前提是：删前实时重扫、把歧义 / 读不出显式报成「不确定」而不是 0、删除走系统废纸篓、批量操作先列清单确认。

仍未实现：视图菜单的「显示附件目录」开关（`*.assets/` 作为普通文件夹展示）、附件的 vault 内改名 / 删除入口、把引用计数写进索引（现在是按需全库扫描，不落 SQLite）、`.assets/` 里非图片 / PDF 的其他文件不进树。📎 徽标目前常显而不是悬停才显。
