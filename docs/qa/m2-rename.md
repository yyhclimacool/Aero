# M2 重命名同步链接验收

更新日期：2026-09-21（aliases / 索引时序补充）。旧范围与自动化记录的原日期为 2026-09-17，以下保留，不代表当日复跑结果。

## 原有功能范围（2026-09-17）

从编辑器标题处重命名同目录下的 Markdown 文件，同时改写当前 vault 内实际解析到旧笔记的 Wikilink 和笔记嵌入。扫描遵守 vault 的忽略规则，不依赖索引是否齐全。

- 保留 `|别名`、`#标题`、`#^块`、链接内空白和表格 `\|`；正文其他字节、BOM、混合 CRLF/LF、末尾换行保持原样。
- 不碰代码、数学、转义文本、未解析 / 歧义链接及指向同名其他笔记的链接。仍可用的 front matter 标题链接不改写。
- 默认沿用短名称或路径写法；新名称会导致错误匹配时改用经解析验证的限定路径。无法写出不歧义的目标则停止。
- `.assets/` 目录随笔记移动；若目标附件目录已经存在，操作开始前拒绝，原笔记不动。
- 保存失败或正在保存时不开始；准备期间继续编辑则取消。超过 20 个其他文件时确认实际影响数量，可取消。
- 完成后编辑器使用新路径，更新自引用、文件树、搜索及反链；后续保存不会复活旧文件。索引启动同步期间的更新会延后执行。

## 失败与恢复

准备计划只读磁盘；提交前校验笔记列表、文件指纹和待改写文件原文。所有原件先写入 `.aero/rename-<id>/`，Unix 下恢复目录权限为 `0700`，`manifest.toml` 记录原路径和备份文件对应关系。成功后删除恢复目录。

提交时逐文件再次校验，普通写入失败逆序回滚已改写文件，再恢复原文件名及附件目录。回滚发现新的外部内容时保留它并报告未完成项，绝不直接用旧备份覆盖；恢复目录保留，通知包含路径。遇到进程中止也可按 manifest 对照检查新旧笔记和附件，再人工恢复原件。

这不是跨文件的崩溃原子事务；外部程序在最终校验与原子替换之间的竞争仍存在。当前提交阶段在 UI 回调中串行执行，以免编辑器自动保存或监听处理插入文件迁移与编辑器换路径之间；超大批量操作的 UI 延迟尚未验收。

```sh
cargo fmt -p aero-core -p aero-index -p aero-app -- --check
cargo test --locked --offline -p aero-core -p aero-index -p aero-app
```

新增 core 测试覆盖原始字节保留、嵌入、同名与标题解析、新名称转义、过期计划、目标冲突、部分写入失败回滚、回滚时外部改动保护及附件冲突。新增 GPUI 测试覆盖整条重命名 → 编辑器 / 文件树 / 搜索 / 反链 → 再次编辑保存的链路、准备期间编辑取消、批量确认的取消与接受，以及等待启动索引完成后应用更新。原保存失败阻止切换的回归也增加了重命名断言。

## 2026-09-21 别名与索引时序

- 解析同时使用真实 front matter 的 title / aliases；改名后仍能解析到目标的别名链接保留原写法，正文中的 `title:` 不作为笔记标题。
- 保存、重命名与重载触发的索引写入按提交顺序执行；搜索、反链和目录查询等待调用前已提交的写入。启动期间重命名在队列中等待同步，后续保存不能越过它。
- 连续改名时，中间路径可能在索引任务执行前已经消失；迁移失败后按当前磁盘状态校准旧 / 新路径，避免残留旧索引。
- 关闭仍在当前线程停止同步并释放 zvec；取消未开始的任务并唤醒等待者，不等待队列排空。

新增确定性回归覆盖错误后继续、查询提交边界、保存 → 改名 → 重载、连续两次改名、启动等待及关闭期间的待执行任务。2026-09-21 索引服务 11 项与工作区重命名回归通过，全量 395 项通过；日志与分项计数见 [补全记录](m2-completion.md)。
