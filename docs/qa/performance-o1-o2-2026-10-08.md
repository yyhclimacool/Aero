# O1 / O2 首批优化验收（2026-10-08）

实施顺序先写入 `docs/project_plan.md` 第 19.1 节，再修改源码。基线为 `92b58f8`，本记录对应当前工作区中的首批改动。

## 交付范围

- **字数增量维护**：`Document` 初始化时计算一次；插入、删除、替换、撤销、重做和失败事务回滚按改动范围更新，包含左右词边界。保持原有 CJK 按字、其他字母数字连续串按词计的规则。状态栏不再物化全文。
- **后台嵌入扫描**：使用 Rope 快照，在后台物化和扫描；同一编辑器最多一个扫描任务，后续编辑合并，已完成扫描后的变更延迟 100 ms 取最新快照。按文档版本、I/O 会话代次和路径校验结果；嵌入读取另用请求号防止已移除缓存被旧回复复活。Resolver 更新后重新预取，外部改动能替换正在读取的旧缓存。
- **文件树刷新**：新建、日记、删除、附件操作及编辑器触碰路径均请求后台扫描。新建 / Finder Markdown 导入的命名使用已缓存路径集合和候选路径存在性检查，不再为名字全库枚举；新建使用 create-only，避免覆盖外部刚创建的文件。后台刷新保留显式选中、定位和操作错误。
- **首次文本解析**：无状态 TextView 创建时直接传入最终 Markdown 扩展，避免先按默认配置解析再替换配置。回归用固定的小 / 大文档夹具，分别覆盖同步 / 后台解析；显式重绘五次后，解析调用数保持不变。
- **验收入口**：`scripts/check-m1.sh` 补入 `aero-embedding`；核心新增 `word_count_bench` 示例。

O2 的低风险目录刷新部分已完成。Finder 文件读取 / 创建、附件引用全库改写及其余同步文件 I/O 尚未全部移到后台；O3–O6 未在本批实施。

## 字数统计微基准

复跑：`cargo run --locked -p aero-core --example word_count_bench`。

debug 构建，每种路径预热 10 次、记录 100 次。中英混排单段文档，每次在开头插入 `x `，统计后撤销。两条路径都包含相同的 `Document::edit`；对照路径随后物化 Rope 并全文计数，优化路径直接读取增量维护的字段。文档初始化、撤销、解析、单位更新、布局和绘制不计入计时。原始结果见 [CSV](results/2026-10-08-word-count.csv)。

| 文档字节数 | 全文扫描 p50 / p95 | 增量统计 p50 / p95 |
| --- | --- | --- |
| 1,048,572（约 1 MiB） | 10.83 / 11.21 ms | 3.38 / 3.54 µs |
| 10,485,756（约 10 MiB） | 116.23 / 147.40 ms | 3.62 / 3.88 µs |

这证明移除了字数统计随文档长度增长的扫描开销。测试在较少块的单段文档上运行，不能外推为大量 Anchor 的编辑耗时，也不是 GUI 输入到呈现指标。未测本轮嵌入扫描的耗时分布、GUI 输入 p99、持续滚动帧率或参考 M2 的内存预算；后续阶段继续补齐固定场景和完整管线测量。
