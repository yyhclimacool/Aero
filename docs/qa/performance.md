# M1 性能验收

2026-09-16，Apple M5 Pro / 48 GiB / macOS 26.6.2 / Rust 1.98.1，release profile。
这不是计划的 M2 / 16 GB 参考机器；结果不能直接宣称参考机验收通过。

## 方法

运行 `cargo run --locked --release -p aero-index --example m1_bench -- 10000` 或 `100000`。
基准生成独立临时 vault 和索引，平均每篇约 2.87 KB、13 个可索引块，含中英文、Markdown、链接、标签；退出后清理。内容刻意可重复，不能替代真实个人笔记库的语料与查询质量验收。

- 全量重建：新建 Indexer → 全库扫描/读取 → Document 解析 → SQLite 元数据 → zvec FTS → flush + optimize。生成测试文件的时间不计入。
- 搜索：7 类查询，先各预热一次，再做 210 次；取最近秩 p95。包含中文、英文多词、标签和无命中短语，非空查询同时校验确实有结果。
- 增量：30 篇不同笔记；从原子保存完成开始，经过解析/SQLite/FTS 写入，再搜索新增关键词并确认命中对应笔记。记录最大值。
- 文档：约 1/10 MiB 的有效 UTF-8 Markdown，记录 Document 构造；分别做 20 次单字节编辑和整篇重解析，p99 在这个小样本下等于最大值。这是定位同步解析成本的诊断，不是实际 GUI 的输入 p99。
- 内存：`/usr/bin/time -l` 的最大 RSS 是整个基准进程的峰值，包含索引、文档解析等阶段。不能据此当作“打开 10 个文档时的 GUI 常驻内存”。

100k 模式内置三个索引绝对预算，任一个不满足即非零退出；没有 `continue-on-error` 或放宽阈值。GUI、内存、相对 20% 回归门禁尚未实现。

## 首轮记录

首轮与其他构建/验收任务有部分并行，因此 100k 的临界结果安排了单独复测。

| 指标 | 10k | 100k 首轮 | 计划预算 |
| --- | ---: | ---: | --- |
| 全量重建（含 optimize） | 21.973 s | 189.058 s | 100k < 180 s |
| 全文搜索 p95 | 4.915 ms | 54.091 ms | 100k < 50 ms |
| 保存后到可搜索，30 次最大值 | 2.391 ms | 3.187 ms | < 300 ms |
| 1 MiB Document 构造 | 10.530 ms | 14.783 ms | GUI 首帧 < 100 ms，不能等同 |
| 10 MiB Document 构造 | 128.989 ms | 128.564 ms | GUI 首帧 < 1 s，不能等同 |
| 1 MiB 编辑＋重解析，20 次 p99 | 9.367 ms | 11.308 ms | GUI 输入到绘制 p99 < 16 ms |
| 10 MiB 编辑＋重解析，20 次 p99 | 105.343 ms | 107.394 ms | 同上；仅 CPU 阶段已超预算 |

## wikilink 索引接入后的复测（2026-09-16 晚）

wikilink 让每篇多了 `links` 表写入（基准语料每篇 12 条、全部可解析）与保存后的入链重判。同机同时段把 M1 基线二进制与当前代码背靠背各跑一次 100k 作对照（此时机器明显比上午慢：基线自己的全量重建从 169.7 s 变成 193.2 s，纯 CPU 的 1 MiB Document 构造也从 9.3 ms 变成 13.5 ms）。

| 指标 | 基线二进制（同时段） | 当前 | 备注 |
| --- | ---: | ---: | --- |
| 全量重建（含 optimize） | 193.160 s | 199.362 s | +3%；1.2M 行 `links` 写入。两者都超 180 s 预算，预算需在参考机复核 |
| 全文搜索 p95 | 49.674 ms | 78.424 ms | 搜索代码未变；同一二进制前一轮 49.464 ms，视为噪声 |
| 保存后到可搜索，30 次最大值 | 2.605 ms | 7.079 ms | 修正前 19.155 ms：被引用 1200 次的笔记每次保存都重判全部入链；现只在新建 / 改标题 / 重命名 / 删除时重判 |
| 10k 全量重建 / 搜索 p95 / 保存 | 17.997 s / 5.565 ms / 2.830 ms | 17.280 s / 5.247 ms / 3.510 ms | 沙箱内背靠背 |

优化项：标签抽取与 wikilink 扫描共用一次 comrak 解析；全量同步给新文件预分配 `note_id`，链接入库即解析，行按 256 篇一个事务攒批；同步结束只重判"未解析 + 名字有竞争"的行。

原始数据：[基线复跑](results/2026-09-16-bench-100k-baseline-rerun.jsonl)、[当前](results/2026-09-16-bench-100k-links.jsonl)。

## 尚未验收的 GUI 指标

- 冷启动到可交互 < 500 ms：需要实际应用的启动/首帧时间点；不能用 Indexer 打开或 Document 构造代替。
- 1/10 MiB 文件首帧：需包含读取、解析、视图构造、布局与实际 GPU 绘制。
- 输入到绘制 p99 < 16 ms、长文档 60 fps：需真实窗口事件与呈现时序；当前同步整篇解析的 10 MiB 成本已经提示架构缺口。
- 10k vault 打开 10 文档的常驻内存 < 300 MB：当前产品仅持有一个活动编辑器，需要先明确该验收场景；此次未冒充通过。
- 固定参考机器、真实笔记语料、nightly 历史基线及 20% 回归门禁仍待补齐。
